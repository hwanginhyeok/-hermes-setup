# 병렬 작업 전략 (Parallel Strategies)

## 1. 작업 분해 원칙

### 독립성
- **파일 기반 분리**: 각 워커가 다른 파일을 건드리지 않도록
  - w1: `src/web/chart_api.py` (시그널)
  - w2: `src/web/tesla_api.py` (텍스트 데이터)
  - w3: `src/web/static/tesla.html` (UI/시각화)

- **기능 기반 분리**: 관련 없는 기능은 같은 워커에서도 OK
  - 예: w1에서 1-52/1-58/1-59 전부 (모두 차트/시그널)
  - 예: w2에서 1-60/텍스트 데이터/문서 정리

### 순서 의존
```
w1: API 엔드포인트 생성 → 
w2: 데이터 생성 → 
w3: UI 렌더링 + 통합
```

## 2. 병렬 패턴

### 패턴 A: 단일 태스크 병렬화
대상: 큰 태스크를 하위 작업으로 쪼개서 병렬

```
원본: 1-58 트레이딩 차트 반영
분해:
  - w1: sma_signals.py 정배열/역배열 시그널 함수
  - w2: 과거 매수 시그널 발동 N일 후 수익률 계산
  - w3: 차트에 시그널 마커 + 채널 가이드
```

### 패턴 B: 독립 하위 태스크 동시 진행
대상: 서로 영향 없는 하위 태스크

```
PREPARED에 있는 P1 태스크 3개:
  - 1-46 stock-notion-sync
  - 1-47 migration
  - 1-53 빗각 채널 시그널

동시 할당:
  w1: 1-47 migration
  w2: 1-46 PoC
  w3: 1-53 시그널
```

### 패턴 C: 검증/테스트 병렬화
대상: 여러 환경/조건에서 검증

```
API 수정 후 테스트:
  - w1: API 정상 응답 확인
  - w2: 빈 데이터셋에서 동작 확인
  - w3: 대용량 데이터셋에서 성능 확인
```

## 3. 병렬 작업 주의사항

### 충돌 방지
1. **git 브랜치**: 각 워커가 feature 브랜치 생성 후 커밋
2. **공유 리소스**: DB/API 호출은 병렬 문제 없이야 함
3. **상태 관리**: 진행 상태를 파일로 기록하여 중복 작업 방지

### 병렬 제어
- **동시 시작**: 3개 워커에 동시에 명령 전송
- **개별 완료**: 각 워커가 완료 보고하면 PM이 확인
- **전체 완료**: 3개 완료 후 통합 커밋 + PR

## 4. 병렬 효율 측정

```
개별 소요: 60분/작업 × 3개 = 180분
병렬 소요: max(60분, 65분, 55분) = 65분

절감 효과: 115분 (64%)
```

## 5. 실패 복구

### 개별 실패
- w1 실패: w2/w3 계속 진행, w1만 재시도
- PM이 개별 워커 상태 모니터링

### 전체 실패
- PM이 실패 원인 분석 후 재계획
- 워커 3개 전부 해제 후 재할당
